# 第四部分：本机 Origin 绘图与细部设置方案

## 当前检查结果

网站的单自变量和双自变量拟合目前生成 Python 图像、数值文件和 Origin 导入脚本。`fitting_service.py` 明确将 Origin 能力标记为 `export_only`。

本机注册了 `Origin.Application` 和 `Origin.ApplicationSI`，注册的可执行文件存在，产品版本为 Origin 10.2。网站当前 Python 环境未找到 `originpro`、`OriginExt` 或 `win32com`。接口已注册不能代表许可证和自动绘图已经验收。

## 推荐方式

由现有 Python 程序负责拟合和模型评价，Origin 使用已经保存的观测点、预测值和响应面网格绘图。修改样式只重新绘图，不重新拟合。

优先通过 Origin 官方的 `originpro` 外部 Python 接口连接本机 Origin。与直接编写完整 COM/LabTalk 自动化相比，该方式更容易维护。现有交换包和导入脚本继续保留，联动失败时明确显示失败原因。

本轮覆盖通用数据拟合及双自变量拟合；其他三个研究模块不改动。

## 页面操作

拟合结果中提供“调用 Origin 绘图”“在 Origin 中继续编辑”和图像预览。绘图设置属于单独的任务配置，记录来源拟合任务及模型，允许从已完成的拟合结果重复出图。

提供常用与高级两级细部设置：

| 类别 | 设置项 |
| --- | --- |
| 图形内容 | 本轮单变量散点与拟合线、双变量响应面；残差、等高线和切片仍使用原有绘图输出 |
| 字体 | 字体名称、字号，标题、轴标题、刻度、图例分别设置 |
| 线与点 | 线型、线宽、颜色、符号形状、大小、透明度 |
| 坐标轴 | 标题与单位、上下限、X/Y线性或对数、主次刻度数量、X/Y反向 |
| 图例与版面 | 图例位置、是否显示边框、网格线、页面宽高（mm）；文字可在Origin中编辑 |
| 三维图 | 视角、色带、色标范围、色标标题、是否叠加原始散点 |
| 输出 | PNG/TIFF 分辨率与物理尺寸、PDF/SVG输出、可编辑 OPJU 工程；三维可能包含栅格内容 |

与当前图类型不适用的选项隐藏或禁用。需要插值的曲面明确记录数据来源和方法；默认使用已有拟合网格，不对原始数据偷偷重新拟合。导出格式和图类型以本机 Origin 实测支持为准，不将失败的导出列为成功。

## 执行与文件

1. 读取并校验已完成拟合任务的冻结数据。
2. 固化绘图配置和来源模型标识，检查有限数值、正数对数坐标和有效范围。
3. 在独立工作进程中新建本任务专用的 Origin 实例，不复用或清空用户手动打开的工程。
4. 导入观测点、预测曲线或曲面网格，设置列角色和分组，绘图后应用细部设置。
5. 保存 `origin_project.opju`、预览图、选定格式图像、`origin_plot_config.json` 和运行日志。
6. 页面显示真实出图结果、下载链接和失败阶段；文件存在且非空后才登记为输出。

Origin 绘图任务串行，避免多个请求同时控制同一个自动化实例。终止和超时只影响本任务创建的实例。重新绘图不占用腐蚀模拟计算队列；实际并行能力受本机资源和 Origin 许可约束。

“在 Origin 中继续编辑”打开已保存的任务工程；用户编辑不会改变冻结拟合数据。用户在 Origin 中的手动修改不自动反向写回网页设置。

## 验收标准

- 本机真实完成一组二维曲线和一组三维响应面的绘图与导出。
- 改变字体、线宽、轴范围和三维视角后，新图能体现改动。
- 输出 OPJU 可用本机 Origin 打开并继续编辑。
- 修改图像选项前后，拟合参数和原始数据文件哈希不变。
- 缺少软件、联动依赖或许可证不可用时，显示可解释错误，保留原有拟合结果。
- 未提交合法绘图参数时不启动 Origin；超时不会关闭用户已有的 Origin 实例。
- 现有单变量、双变量及启动器回归测试通过。

## 当前边界

本方案已获用户确认并进入实施验收。本机已安装官方 originpro/OriginExt，实际运行版本为 Origin 2025（自动化报告10.250212）。实际支持边界与操作见 `docs/Origin绘图使用说明.md`，初始环境检查记录保留用于追溯。
