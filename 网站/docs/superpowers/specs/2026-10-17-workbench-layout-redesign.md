# 腐蚀研究工作台布局重设计

## 目标

把现有网站改成以研究流程为主线的工作台：用户能快速判断当前阶段、输入来源、下一步操作和结果状态，同时保留 MATLAB、CA–GA、性能对比、APDL、拟合、Origin、任务与历史记录的原有功能。

## 设计方向

采用 taste-skill 的 **Product Performs** 方向。页面将真实的任务状态、预检、运行按钮和结果文件放在工作流上下文中，让界面展示系统正在做什么，而不是只展示参数表。

## 信息架构

- 左侧导航按“采集与模拟、验证与拟合、结果”分组三组。
- 顶部只显示当前阶段标题、服务状态和源码同步入口。
- 主区继续使用现有 panel 与 ID，避免破坏 JavaScript 事件绑定。
- 每个阶段页面保持“输入/来源 → 参数/预检 → 运行/结果”的顺序。
- 结果页将任务状态、核心结果、预览、文件和日志保持为独立视觉区块。

## 视觉规则

- 保留深绿色作为工作台识别色，正文使用深墨色，背景使用暖白和浅绿色分区。
- 页面标题 32–40px，模块标题 21–24px，正文 15–16px，辅助说明不低于 12px。
- 通过字号、留白和浅色背景区分层级，减少重复细线和低对比度小字。
- 只使用平面色块和轻微边界，不改变功能状态颜色的语义。
- 移动端将侧栏折叠为横向流程栏，表单和结果改为单列。

## 约束

- 不修改后端 API、任务目录、输入文件类型、参数路径、MATLAB/Python/APDL/Origin 调用和输出格式。
- 不删除既有导航入口；只重新分组、命名和视觉排列。
- 不覆盖已有结果和历史任务。

## 验收标准

1. 页面加载后保留 8 个既有 panel 及其原 ID。
2. 侧栏显示三个流程组，所有入口仍可点击切换。
3. 主要文字在桌面和移动视口下达到新的字号层级，没有横向溢出。
4. 任务结果页仍能显示 Origin 预览、继续编辑按钮和下载文件。
5. 前端现有测试与新增布局结构测试通过。
