# 性能对比第二轮优化与验收记录

日期：2026-10-15。增量更新现有 `codex/performance-comparison` 分支及 PR #1。只修改网站辅助执行、接口、页面、测试和文档；原 CA、GA、MATLAB 科学源码不变。

## 本轮实现

| 项目 | 行为与边界 |
| --- | --- |
| 本机环境诊断 | 软件包存在、原生扩展导入、CPU/GPU最小内核分别检查；三个独立子进程保留日志、实际架构、原因及超时。安装成功不代表能运行。 |
| 运行库加载 | 可显式设置 `CORROSION_NATIVE_DLL_DIR`，仅加载当前进程及子进程的已有运行库，记录路径和SHA；不安装系统组件、不修改PATH或注册表。 |
| 池生命周期 | `recreate` 每次建立池；`persistent` 首次建立、后续复用；原适应度函数及科学随机数规则不改。显式spawn，结束或异常均关闭池。 |
| 线程与预算 | 进程数×每进程线程数不超过CPU预算及本机逻辑CPU数；Taichi实际线程配置受检验；BLAS/OpenMP线程环境在子进程明确设置。 |
| 测量矩阵 | 最多3种子、4种进程数、两种池；固定或可复现的打乱顺序；每个种子都运行本次新NumPy基准，按baseline_id配对，基准在后执行也能补齐对照。 |
| 负载口径 | 固定种群一代CA适应度；短程原GA保留选择、交叉、变异和早停，记录最大/实际代数。选择数量显式可调且小于种群，避免原选择循环无法选足个体。 |
| 来源阶段 | 冻结已完成模拟的阶段NPZ、SHA、行列层数和物理间距；从来源阶段+1运行；拒绝形状或间距不一致，不重采样。重试从旧任务冻结副本读取，不依赖原任务文件仍存在。 |
| 计时与解读 | 首次、初始化、读取、预热样本、数值导出、对照、总墙钟分开；中位数、Q1/Q3/IQR、波动率、低样本提示。固定种群的objv为六项误差，短程GA为最终四项误差。 |
| 数值与物理差异 | 分块比较数组；分类a必须完全一致，另报变化数/比例。显示表面深度差图、实际六指标与缺失原因。固定种群选NumPy最优索引，在候选中取同索引对照，并另报候选自己的最优索引。 |
| I/O与导出 | 每方案只更新轻量JSON/CSV；首次/末次NPZ默认保留，明细可选清理。ZIP按需生成并缓存不可变版本，含冻结来源与相对路径说明。跨进程文件锁协调打包和清理；清理超时/失败只提示，保留计算结论。 |
| 停止和重试 | 新服务停止旧worker前校验PID、创建时间、锁、命令行、cwd及运行目录；失败项重试创建新任务并重新测基准。未完成测速不支持检查点续算。 |
| 采用方案 | 先展示配置差异，用户确认才改正式模拟模式和worker；种子默认保持。NumPy严格模式仍单worker，不把性能实验中的NumPy并行伪装为严格恢复支持。 |

## 验证证据

- Python全量回归：152项通过（102.450秒）；覆盖真实NumPy串并行、两种池、三代短程GA、来源阶段、原严格恢复及既有模块。
- Node前端完整回归：42项通过；页面模块语法检查通过。
- 真实Edge浏览器15项验收通过，页面脚本异常0个。两个独立任务均完成5个方案：NumPy单进程、NumPy重建池、NumPy常驻池、Taichi CPU、Taichi GPU。诊断import/CPU/GPU均通过，实际架构为CPU `x64`、GPU `vulkan`。
- 真实网页验证了空种子默认值、非法选择数量拦截、预检、结果表、下载ZIP、重试新基准、采用预览取消/确认及默认保留种子；1440px桌面与390px手机布局检查通过，没有页面整体横向溢出。
- 真实服务接管停止测试：旧服务启动任务并完成首个方案，新服务核验身份后停止同一worker，确认进程退出、部分结果标记取消、ZIP仍可生成。使用隔离的合成任务，未停止用户进程。
- 归档测试验证缓存复用、报告变化生成新版本、旧ZIP字节不变、源NPZ纳入及路径改写、真实独立Python进程争锁；物理绘图失败保留已完成数值对照和加速比。
- 独立代码复核提出的默认种子、来源物理间距、ZIP遗漏来源、清理/打包竞态和清理失败传播问题均已补回归并修正。

本地证据在忽略目录 `output/playwright/v2/`、`.runtime/qa-v2/`、`.runtime/restart-stop-v2/`；原始输入、运行结果、日志、截图、依赖及缓存不上传GitHub。

## 结果不能外推的范围

1. 本轮真实浏览器使用5×6×4小网格和低重复自检，确认流程及设备能运行；不能据此断言某后端对正式模型最快。性能结论需在实际尺寸上重复测试、比较波动和结果差异，并避免其他任务竞争资源。
2. Taichi CPU/GPU真实原CA适应度已运行通过；可选Taichi多进程仍为实验方案，本轮未完成其在不同显卡、较大网格及长时间运行的硬件验收。跨后端不承诺逐位一致。
3. 短程GA保留原迭代规则，但不含正式任务的检查点、绘图、多阶段连续演化和多工况调度开销；来源阶段只冻结该阶段状态，不重跑前序阶段。
4. 50ms父子RSS采样不含GPU显存，可能重计共享页和漏瞬时峰值；1GiB主机数组预算不是实际内存硬上限。线程预算是配置值，不是操作系统线程总数采样。
5. 服务重启接管依赖本版本新增的进程创建时间记录；缺记录、权限不足或身份不匹配时拒绝停止。实际断电、磁盘故障与大文件长时压力不属于本轮验收。
6. ZIP快照按需缓存，历史已下载版本不会因新报告而被覆盖；不同快照会占用额外本地磁盘。取消明细只清理本次试验原始数组，不删除来源快照和已生成的历史归档。
