# APDL前两轮整改与验收

用户批准实施来源一致性、结果与进程可靠性两轮整改，并同步现有GitHub草稿PR。本记录对应复查方案的第1、2阶段；真实MAPDL对照、材料覆盖、网格收敛和性能优化继续留在后续阶段。

## 一、已经落实的行为

| 环节 | 修改后的行为 |
|---|---|
| 同类型换源 | 清除旧任务的阶段和MAT文件选择，避免把A任务的文件名带到B任务 |
| 输入草稿 | `input`即时保存原始字符串，上传、加载来源、刷新返回后按当前草稿重绘；旧请求不能覆盖新来源 |
| 模拟映射 | 只读显示mm、正腐蚀深度与继承间距提示，预检展示实际解析值，payload不再携带旧实测单位/高度值 |
| 双面配准 | 换来源、阶段、文件、变量或映射取消确认；材料/加载变化保留确认但清除预检。后端签名绑定逐面来源身份、SHA和解析映射，提交前重新预检 |
| 节点场 | 按ID匹配真实输入网格，检查初始XYZ及两端UX；缺失网格时尝试读取实际`nodes.dat`，仍缺失则明确未核验 |
| RST | 非空仅表示存在；`rst_validation.state=unverified`、`checks.rst_consistency=null`，总体`validation_state=needs_review` |
| 响应异常 | 零/极弱末步反力、显著反力反转明确提示；保留原始反力符号，EA/L仅比较适用工况的刚度幅值 |
| 状态与计时 | 分开显示读取、几何、写包、MAPDL求解、后处理及待复核；失败保存阶段、耗时和现有执行证据，记录写入错误不替换原求解错误 |
| Windows监管 | 受控启动器等待GO；成功加入kill-on-close Job Object并保存监管身份后才允许真实程序启动，管理句柄不继承 |
| 停止闭环 | 先核验worker身份，再清理求解组，停止worker后再次确认组空；失败显示“停止失败 · 可重试”，保留已有文件 |
| 停止竞争 | 独立`apdl_stop.json`记录停止状态，跨进程`status.guard`锁让worker尊重`stop_failed`；独立停止记录写失败仍尝试保存状态并保留原错 |
| 异常退出 | 死亡worker需核验受控组才认定中断；自主清理失败保持停止重试入口，损坏监管记录不让任务页面直接不可读 |

## 二、数值输出精度

节点CSV使用`(F12.0,8(',',E13.5))`以满足APDL单行128字符限制。无`1P`的Fortran E格式是`0.xxxxxE±nn`，五位有效数字，与Python `%13.5E`不同。节点坐标及加载端UX采用`rtol=5.1e-5, atol=1e-10`容纳合法舍入；固定端UX单独要求接近零。

测试使用真实格式字面值，例如坐标`100.123456`导出为`0.10012E+03`，先复现旧容差误拒绝，再验证修正后通过；超出舍入范围的坐标/位移仍拒绝。原始网格节点和数值输入继续保留原精度，未为通过校核修改几何。

依据：[ANSYS *VWRITE格式与行长说明](https://ansyshelp.ansys.com/public/Views/Secured/corp/v242/en/ans_cmd/Hlp_C_VWRITE.html)、[Intel Fortran E/D格式说明](https://www.intel.com/content/www/us/en/docs/fortran-compiler/developer-guide-reference/2023-0/e-and-d-editing.html)。

## 三、可下载的诊断证据

- `summary.json`：建模/求解状态、`stage_states`、失败阶段、阶段耗时及结果检查。
- `timing.json`：读取、几何、写包、求解、后处理与总耗时；未运行的阶段不伪造耗时。
- `mapdl_execution.json`：实际命令、退出码、日志、求解耗时、监管与清理结果。写入失败会报错，不能认为旧记录是最新最终状态。
- `mapdl_process.json`：任务目录、随机执行身份、启动器PID/创建时间、监管组、清理结果。
- `apdl_stop.json`：停止失败/完成的独立记录；写入失败另报告`stop_persistence_error`。

输入ZIP仍是建模输入包。完整求解日志与后来生成的结果、计时及监管记录在任务文件列表中单独下载，不能认为它们已经全部包含在输入ZIP中。

## 四、验证记录

最终完整回归：后端236项全部通过（127.232秒），前端64项全部通过。后端包括节点/RST、来源与API、Windows受控进程、停止状态竞争、检查点恢复、性能对比和原有工作台行为。自有进程验收不等于真实MAPDL科学验证。

网页在隔离验收运行目录使用明确标注的测试矩阵，实际完成独立双面预检与模型生成：原矩阵5×3，规范化Y/X为3×5，dx/dy为0.3mm，原点10/20mm，实际尺寸1.2×0.6mm，60节点、24单元，最小剩余厚度5.2mm。输出文件可下载，页面明确显示“APDL输入包已生成”，没有生成伪求解反力或应力。

交互核对包括：材料改变保留配准确认、映射翻转取消确认、刷新保留`0.4200`原始输入、实测um/height切模拟后显示mm/depth与继承提示。状态渲染另覆盖未完成建模、正在求解、后处理及RST待复核。

独立审阅曾发现并修复：Fortran精度误判、建模期间过早显示生成完成、停止失败被worker覆盖、自主清理失败失去重试入口、死亡worker未核验求解组、最终写记录错误掩盖原异常，以及停止记录写入失败再次丢失状态。

## 五、验收边界

1. 本机未发现MAPDL，未完成真实ANSYS求解、许可证、MPI或不同ANSYS版本兼容性验证。真实Python父子进程验收只证明监管代码行为，不能代替求解器验收。
2. Windows新任务启用Job Object。旧任务不会自动升级；旧执行记录有PID却缺少监管组记录时拒绝认定“无残留”，需人工在ANSYS中核对。非Windows仅支持显式进程组清理，worker崩溃自动清理不作保证。
3. 本轮未读取二进制RST，不得把“MAPDL求解完成”或CSV检查通过写成完整科学验证通过。矛盾CSV拒绝、RST未核验降级和真实ANSYS基准是不同关口。
4. 本轮未改原CA/GA/MATLAB科学源码、49点MISO、双面装配规则或默认材料/加载参数。原曲线对11mm加载的覆盖、网格质量与收敛、夹持/标距定义仍需后续实算。
5. APDL未实现网页一键续算。已保存的MAPDL重启动文件可下载；停止后的不完整输出不能当作最终结果。

下一步按复查方案第3阶段接入实际MAPDL：先无腐蚀弹性板，再均匀单/双面腐蚀，之后同一非均匀双面数据与原宏对照，最后验证49点MISO非线性与网格收敛。
