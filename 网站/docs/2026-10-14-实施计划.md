# 腐蚀研究工作台重建实施计划

> 本会话继续执行已经确认的需求，采用分工实施和最终独立审查；主代理负责接口集成、启动同步和GitHub交付。

**目标：** 生成可实际调参运行、可恢复和导出、可一键启动同步的中文科研网站。

**架构：** 原生HTML/CSS/JavaScript模块 + 本机Python HTTP API + 任务独立子进程 + MATLAB及网站引擎副本。所有运行文件存入被忽略的`.runtime/`，科研目录不变。

**技术：** Python、NumPy、SciPy、Matplotlib、MATLAB、原生ES模块、Git。

## 全局约束

- 不修改或停止科研原目录和PyCharm进程；不改原CA/GA科学公式、目标组合及随机数规则。
- 不上传输入、结果、日志、密钥或运行缓存；只上传网站源码与说明。
- 每个新增科学行为先写回归测试，实际看到失败后实现；保存测试结果。
- 不假称高速/恢复/后处理已生效，清楚报告实际后端和适用范围。

## 任务1：参数与输入、点云链路

责任：`backend/config.py`、新增`backend/parameter_catalog.py`、`backend/targets.py`、`backend/pointcloud_config.py`、`backend/pointcloud_runner.py`、`matlab/`及对应测试。不得改服务器、前端和模拟运行器。

接口：
- 保持`default_simulation_config()`、`validate_simulation_config(config)`、`validate_targets(value,run_mode)`。
- 新增`simulation_catalog()`返回`[{path,group,key,label,help,type,value,scope,editable}]`，type支持number/integer/boolean/string/array/object/null；覆盖顶层常量、上下界、工况和路径。路径可显示为任务管理范围。原CONFIG_NAMES保留供运行器使用。
- 新增`estimate_resources(config, stages=1)`返回可JSON序列化估算和中文建议，标明估算。
- `inspect_target(path,variable=None,orientation="auto")`返回type、variables、selected、shape、targets、issues、reading_seconds；JSON不含NaN。`load_targets(path,variable=None,orientation="auto")`返回N×6，歧义明确拒绝或提示，非有限值按行列报错。
- 点云catalog现有group/key/value/help/editable保持并补label/type/scope；完整布尔/数组/枚举校验、可调尺寸，点云输出全部在outputs内，源公式不变。

步骤：

- [ ] 实现上述接口，保持旧测试通过；人工核对所有源配置字段。

## 任务2：严格恢复、数值输出和过程信息

责任：`backend/strict_ga.py`、`backend/checkpoint.py`、`backend/runner.py`及新增独立输出/计时模块和对应测试。不得改config、targets、server、worker或前端。

接口：
- 保持`run_simulation(spec,job_dir,progress=None)`，接受run_mode single/staged；正确选择SINGLE_STAGE_GA_CONFIG。进度为扁平JSON对象，包含stage/generation/completed_individuals/total_individuals/phase、timing等。
- 保持`CheckpointStore`接口，可版本化；不可变best快照引用、current/previous备份及哈希、配置绑定、引擎指纹；已有任务兼容应安全拒绝或提供说明。
- 输出`summary.json`、`effective_config.json`、`timing.json`、`stage_metrics.csv`、逐阶段NPZ/PNG、最终兼容simulation.npz。summary含stages（目标、实际六指标、四误差、参数名）、objective_rule、backend/seed、warnings、时间；六指标无法定义时null附说明，不编造。
- 收敛记录与已完成阶段实时导出，数字先存图后生成，输出失败不丢已保存计算。
- 不保留所有阶段的大数组在内存；最终兼容NPZ允许短时栈，但提供资源提示或流式方案。
- 固定种子保持原GA算法和状态传递；严格模式对照原GA和中断恢复。

步骤：
- [ ] 为单阶段配置使用、best/进度一致性、损坏回退、绘图失败仍导出、恢复匹配写失败测试。
- [ ] 实现小元数据检查点与不可变大状态，避免每个体重复全数组；补引擎/环境绑定。
- [ ] 测试原GA一致、单/双阶段以及中断恢复，记录读取/计算/检查点/导出/绘图用时。

## 任务3：专业网页

责任：`frontend/`和`frontend/tests/`，不得编辑后端、脚本、文档。

接口：
- GET`/api/defaults` => simulation, simulation_catalog, pointcloud, capabilities, version。
- POST`/api/config/validate` `{config,run_mode,targets?}` => config,resources,issues。
- POST`/api/uploads?name=...`原始文件体 => id,name；GET`/api/uploads/{id}/inspect?kind=target|pointcloud&variable=...&orientation=auto|rows|columns`。
- POST`/api/jobs`支持simulation `{config,run_mode,targets}`或`{...,upload_id,variable,orientation}`；支持pointcloud现有payload。
- GET`/api/jobs`历史；GET`/api/jobs/{id}` => state,result,progress,elapsed_seconds,files,spec,summary,effective_config,checkpoint可用状态；POST resume/stop；GET log => text；GET download/{filename}。
- POST`/api/jobs/{id}/transfer` => upload记录、目标预览、几何元信息，用于点云结果直接传模拟。
- POST`/api/sync` => git同步结果（用户点按钮才执行）；GET`/api/sync` => 当前分支/远端/状态。
- 多工况POST`/api/batches` `{config,cases:[{case_name,targets?,upload_id?,variable?,orientation?,mode?}],run_mode:"single"|"sequential"|"parallel"|"mixed",parallel_case_workers,sequential_enabled,parallel_enabled}` => batch+jobs；GET`/api/batches/{id}`状态。

步骤：
- [ ] 基于原生模块重建中文专业布局：侧栏/页签、两块独立任务区、流程示意、完整参数分组/搜索/说明与范围、任务记录、数据表格/收敛图/下载/日志。
- [ ] 参数单一状态，导入/导出/默认/模式/种子同步；支持目标上传读取变量/转置及点云两份任意尺寸上传。
- [ ] 固定/自动种子、单/多阶段、资源预检、运行/停止/恢复、历史载入、点云转模拟、一键同步。
- [ ] 编写有意义的JS状态转换测试并执行；做好空状态/报错/忙状态和手机布局。
