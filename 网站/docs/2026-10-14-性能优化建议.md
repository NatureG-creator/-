# CA–GA 腐蚀模拟性能优化建议

本文件把提速建议分成两类：第一类只减少 Python、I/O、绘图和调度开销，必须保持严格模式的数值结果逐项一致；第二类可能改变随机数顺序、浮点舍入、邻域或评估顺序，只能作为明确的“快速试算”开关，不能默认替代严格模式。

## 已实施的低风险优化

1. 每个任务单独保存 `timing.json`；点云 MATLAB 脚本额外保存 `matlab_timing.json`，将读取、预处理、形貌分析、数值导出、图片导出和目标导出拆开。形貌分析包含过程图生成，进程总耗时还包含 MATLAB 启动时间。
2. 模拟结果记录主进程 `peak_memory_bytes`（`psutil`）以及 Python、NumPy、SciPy、Taichi 版本和 Git commit，便于复现实验和比较优化前后环境。主进程峰值不含子进程和 GPU，不能当作任务总峰值。
3. 点云预检采用确定性采样显示，并增加重复点和零跨度坐标轴诊断；诊断不修改原始数据，也不参与 MATLAB 科学计算。
4. 多工况可以整批停止、从检查点重试失败工况，并将批次状态、任务配置、输出文件和日志打包为 ZIP，减少人工逐个导出造成的等待。

## 优先级最高的提速方向

### A. 不改变结果的优化

- 严格模式继续保持 `parallel_workers=1`、固定随机种子和原有评估顺序。先用 `5×6×4` 小网格、`F=3`、`nind=4`、`maxgen=3` 做基准，再扩大规模。
- 将固定几何网格的邻域索引、边界掩码和坐标映射预计算一次，在每个个体评估中复用；必须与原 CA 输出逐元素比较。
- 减少不必要的 `np.stack`、深拷贝和跨进程数组复制，优先复用只读几何数组；不得复用会被 CA 原地修改的状态数组。
- 只在代末和阶段末绘图，保留每代收敛 CSV；绘图与 GA 评估解耦，避免 Matplotlib 阻塞主计算。
- 保持流式 NPZ/CSV 导出，避免所有阶段体数组同时驻留内存；检查点只在完整个体提交、代末和阶段边界写入。
- 批次中复用已创建的进程池，避免每个阶段重复初始化 worker；缓存只能绑定完整配置、目标哈希、随机种子和引擎指纹。

### B. 需要独立开关的快速试算

以下任一项都可能改变结果，必须与严格模式分别标记和验证：`float32`、Numba/Taichi 后端、改变随机数调用顺序、改变并行评估顺序、减少 `F`/GA 代数/种群、近似六指标、改变 CA 邻域、改变边界处理、减少检查点频率。

## 验收方法

对每个候选优化保存两份输出，逐项比较：`perfect_parameter`、`perfect_result`、`perfect_a`、`perfect_d`、`perfect_cl`、四项误差、六指标、阶段收敛记录和最终 `simulation.npz`。严格模式只有在数组逐项一致时才可标记为“结果不变的提速”。

同时记录：总耗时、输入读取耗时、计算耗时、检查点耗时、绘图耗时、导出耗时、峰值内存、元胞更新数和进程数。MATLAB 与 Taichi/GPU 需要在真实可调用环境中单独验证，本地没有这些依赖时不能把静态测试当成运行证明。

## 当前建议顺序

先用新增的 `timing.json` 找出真实瓶颈，再做固定网格预计算和数组复制削减；随后比较绘图/导出异步化；最后才评估 Taichi、`float32` 或减少迭代等快速试算开关。任何提速提交都应保留原始基准输出和配置指纹。
